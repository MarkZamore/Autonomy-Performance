# Брокер Windows, выпуск 32

Фиксированный каталог и native-адаптер идентичны JustEnoughTools. Модели и COM-объекты целиком обслуживаются в MTA текущего процесса и исходного пользователя. Только Value/PossibleValues и флаги модели; UI/action Invoke, Settings и другой пользователь не используются. Типы, диапазоны, политика, доступность и ограниченная проверка нескольких свежих моделей защищают от оптимистичного readback. Ошибка не вызывает обход политики или повторную запись реестра.

Новые сопоставления и порядок строковых вариантов разрешены на проверенной Windows 26300.9711. На другой сборке сохраняются прежние адресные системные API. Режим питания активного источника меняет брокер; неактивный источник изменяется AC/DC API, поскольку его модель может быть отключена Windows. Тайм-ауты сна/экрана проверяются независимо для AC/DC; 3 минуты — третий вариант, «Никогда» — последний. Энергосбережение дополнительно подтверждается уведомлением эффективного состояния. Восстановление автоматического override 0 сохраняет специальный нативный путь.

На основной ОС с отдельным разрешением временно переключены и восстановлены энергосбережение, активный режим питания, AC/DC тайм-ауты, адаптивная яркость, четыре предпочтения присутствия и USB. Настоящий production-исполнитель дополнительно прошёл три режима каждого источника, оба варианта тайм-аутов/адаптивной яркости и энергосбережение. Readback powrprof и исходные значения проверены независимо от брокера. Яркость и HDR проверены отдельным адресным тестом с восстановлением. Аппаратный эффект присутствия/USB по будущему физическому событию не имитировался: подтверждены сохранённые предпочтения модели.

Адресные разрешение, частота, масштаб, HDR, CABC и яркость выбранного монитора остаются на существующих API: скалярная модель Settings не предоставляет подтверждённого соответствия выбранному MonitorId. Полная тема, заставка, громкость и OEM/сторонние компоненты также не заменяются UI-действиями брокера. Это сохранённые работающие механизмы, а не удалённые функции.

VerifyBrokerPreferences проверяет подставные состояния, политику, неприменимость, незавершённую операцию, явный fallback неактивного контекста, неожиданный тип, неподтверждённую запись, локализованные варианты и повторное применение без изменений ОС. VerifyQueuedScrolling проверяет обе ветви анимации без изменения системного предпочтения.

Совпадение текущего Boolean энергосбережения не доказывает принудительный override. После broker OK отдельно проверяется 1 (On) / 2 (Off); автоматический 0 доводится до явного контекста прежним WNF-адаптером с проверкой эффективного состояния. Совпадающий Boolean повторно не отправляется: этот Windows control может вести себя как toggle. Реальная проверка automatic 0 → forced 2 и automatic 0 → forced 1 прошла; исходный override 2 восстановлен. 22 дополнительных теста подставляют broker, чтение override, native setter и эффективный observer; ошибки и политики не обходятся.
