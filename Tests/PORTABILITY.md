# Проверка через Process Monitor

Наблюдатель не входит в приложение. Он требует отдельно полученный официальный Microsoft Process Monitor, его конфигурацию с включёнными файловыми, реестровыми и процессными событиями и стандартное подтверждение UAC. Не отключайте защиту Windows. Сам конструктор запускайте отдельно с обычными правами.

`TracePortability.ps1` проверяет подпись Microsoft, отказывается мешать существующему Procmon и хранит журнал в `Tests/Artifacts/Portability/<сеанс>`. Пути к Procmon и конфигурации передаются явно через `-ProcmonPath` и `-ConfigPath`. Используйте Windows PowerShell 5.1. Утилита не включается в GitHub-проект.

1. Запустите наблюдатель, задав `-ExpectedSaveDirectory` и `-ExpectedDestination` для тестового сохранения.
2. После появления `ready.json` запустите корневой EXE обычным пользователем. Запишите PID в `application.json` внутри сеанса: `{"ProcessId":1234}`.
3. Выберите пресет, сохраните EXE через настоящий системный диалог, повторно откройте диалог и отмените его, закройте конструктор. Не запускайте полученный режим, если проверяете только конструктор.
4. Создайте пустой `stop.request` в каталоге сеанса. Наблюдатель остановит только свой единственный Procmon и преобразует PML в CSV. Успех отмечается в `finished.json` после проверки конвертации. Запись ограничена по времени.
5. Выполните `AnalyzePortability.ps1 -SessionDirectory <сеанс>`. Он разделяет фактические изменения, открытие существующих объектов и попытки записи. Включение дочерних процессов основано на событиях создания процессов.

Сохранившийся PML можно преобразовать без повторения сценария: `TracePortability.ps1 -ProcmonPath <Procmon64.exe> -SessionDirectory <сеанс> -ConvertOnly`.

`RegCreateKey` с результатом открытия существующего ключа не считается созданием. `CreateFile` само по себе не доказывает запись: учитываются результат открытия и последующие операции. В то же время записи стандартного диалога или библиотек под PID конструктора не скрываются из отчёта. Действия общих служб Windows требуют отдельного доказательства связи с приложением.

PML/CSV могут содержать приватные пути и данные других процессов. Они исключены из Git вместе с `Tests/Artifacts`. Для публикации используйте только проверенное обезличенное описание результатов.

Портативность означает отсутствие установки и собственных постоянных настроек, а не отсутствие всех следов Windows. Текущий экспорт использует временный `.ap-*.tmp` в выбранной папке. При штатном завершении он исчезает; аварийное завершение может оставить его. Системные диалоги, Windows и .NET могут изменять собственную историю и кэши.
