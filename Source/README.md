# Автономность и производительность

Портативный конструктор для Windows 11 x64 — Autonomy&Performance.exe в корне проекта. Дополнительная установка не требуется: используются включённый в Windows .NET Framework 4.8 и системные API. Программа и создаваемые EXE работают по отдельности.

## Использование

Слева раскройте нужные категории и выберите действия. Справа находится нумерованный предпросмотр, который можно выделить и скопировать. Внизу слева — пресеты «Автономность» и «Производительность»: они заменяют действия целиком, отключают изменение частоты дисплея и дополнительные функции и сохраняют выбранную иконку. После выбора пресета настройки можно изменить вручную. Нажатие пресета не применяет настройки к компьютеру и не создаёт файл.

«Автономность»: включить энергосбережение и тихий режим вентиляторов. «Производительность»: выключить энергосбережение, выбрать производительный режим вентиляторов и оптимальную производительность Windows, установить яркость 100%. Управление громкостью удалено.

Бинарные функции управляются трёхпозиционным тумблером справа: выключить / не менять / включить. По умолчанию — не менять. Режимы вентиляторов и питания выбираются взаимно исключающимися чекбоксами без отдельного «Не менять»: повторное нажатие снимает выбор, все снятые галочки исключают действие. Нажатие значка солнца включает и отключает ползунок яркости 0–100%, сохраняя его значение. Выключенный значок исключает яркость из конфигурации. Подсказка при наведении оставлена только у кнопки «Выбрать иконку»; доступные названия элементов для экранного диктора сохранены.

Вместо категории «Вентиляторы» используется ScreenXpert с его иконкой. Режимы соответствуют приложению: высокая производительность, стандартный, тихий. Стандартный хранится как FanProfile=3 и перед отправкой ASUS преобразуется в нативный профиль 0; нативный профиль 3 (FullSpeed) этот пункт не включает. Сохранение невыбранных пользовательских режимов питания AC/DC действует и для стандартного профиля.

Wallpaper Engine: WallpaperPlayback=0 не меняет обои, 1 продолжает, 2 ставит все обои на паузу. Исполнитель находит уже работающий wallpaper32.exe/wallpaper64.exe в текущем сеансе и проверяет ProductName. Путь определяется на целевом компьютере, не сохраняется в конфигурацию. Используются документированные [CLI-команды](https://help.wallpaperengine.io/ru/functionality/cli.html) `-control play` и `-control pause`, без оболочки и видимого окна. Отдельный командный процесс ожидается не более 2,5 секунды; при зависании завершается только он. Если основного процесса нет или он недоступен, действие пропускается без запуска приложения из Steam/реестра. У CLI нет отдельного запроса состояния паузы; успех означает штатное завершение отправителя команды. Правила автоматической паузы Wallpaper Engine продолжают действовать.

ARMOURY CRATE пока содержит только заголовок с иконкой, без действий. Контурные иконки категорий встроены в конструктор из CategoryIcons.xaml и сохраняют форму значков приложений; прежние растровые изображения не используются. Установленные приложения нужны лишь для соответствующих действий исполнителя. Команды внешнему приложению могут вызывать его собственное ведение файлов и журналов; отсутствие любых системных/сторонних записей не обещается.

Кнопка иконки открывает пять встроенных вариантов и выбор пользовательского ICO. Выбор встроенной иконки действует до закрытия программы. Пользовательская ICO сбрасывается после успешного сохранения; если файл удалён, используется иконка программы. При каждом сохранении открывается выбор места и имени, первоначально на рабочем столе, с именем Режим.exe.

В разделе дисплея можно изменить частоту одного экрана без дополнительного чекбокса: пункт «Не менять» исключает действие. Список зависит от текущего разрешения и возможностей драйвера. EXE запоминает идентификатор монитора и при запуске заново проверяет доступность режима. Отключённый монитор или недоступная частота молча пропускаются. То же правило действует для HDR в «Дополнительно»: используется выбранный в разделе «Дисплей» экран. Скрипт продолжает другие действия, не ждёт подключения и не активирует другой экран. Выключенный кнопкой монитор может оставаться активным для Windows; тогда его параметры доступны. Яркость задаётся отдельно для активных панелей с WMI-поддержкой. Разрешение и частота другого экрана не меняются. Клонированные источники с несколькими мониторами не предлагаются.

## Дополнительные действия

| Настройка | Включить | Выключить | Механизм |
|---|---|---|---|
| Тёмная тема | Тёмная тема Windows и приложений | Светлая тема | Существующие пользовательские параметры Personalize и уведомление Windows |
| Сон через 3 минуты | 180 секунд бездействия для AC/DC | Автоматический сон по таймеру отключён | PowerWriteAC/DCValueIndex |
| Экран через 3 минуты | 180 секунд бездействия для AC/DC | Выключение экрана по таймеру отключено | PowerWriteAC/DCValueIndex |
| HDR | HDR выбранного экрана включён | Выключен | CCD DisplayConfigGet/SetDeviceInfo |
| Экран при уходе | Lock on Leave | Функция выключена | HumanPresenceSettings; нужен датчик и разрешение Windows |
| Затемнение при отведении взгляда | Adaptive Dimming | Функция выключена | HumanPresenceSettings; нужна поддержка датчика |
| Яркость по содержимому | CABC всегда, от сети и батареи | CABC выключен | Служебный CCD-канал установленного приложения «Параметры», выбранный экран |
| Автояркость по освещению | ADAPTBRIGHT включён для AC/DC | Выключен | Штатная политика питания; эффект зависит от датчика |
| Заставка | Включить уже настроенную заставку | Выключить | SystemParametersInfo; отсутствующая заставка не устанавливается |
| USB при выключенном экране | Экономия включена | Выключена | Существующий параметр Windows AutomaticSurpriseRemoval; без смены прав |

Положение «Не менять» не вызывает установку соответствующего параметра. Таймеры независимы: изменение сна не переписывает невыбранный таймер экрана. После обновления схемы выбранный режим питания AC/DC применяется последним; если режим не выбран, исходный пользовательский выбор сохраняется. При запрете записи или отсутствии функции шаг молча пропускается, остальные продолжаются. При уходе гарантируется только включение системной функции выключения экрана; последующий сон определяет Windows.

Яркость применяется после изменения частоты/HDR/CABC, чтобы переход драйвера не сбросил выбранный процент. Если скрипт отключает энергосбережение, это делается до HDR; включение энергосбережения выполняется последним. Неотмеченные функции при этом не включаются и не отключаются автоматически.

HDR и CABC привязаны к тому же идентификатору дисплея, что и частота. CABC не подменяется автояркостью от освещения. Служебные пакеты CABC (`GET -36`, `SET -35`, 24 байта) определены по установленному SettingsHandlers_PCDisplay.dll версии 10.0.26100.9549; значения 0 — выкл., 1 — всегда, 2 — только батарея. Конструктор экспортирует только 0 или 1. Это внутренний интерфейс: разрешено проверенное семейство компонента 10.0.26100.*, дополнительно проверяется успешный запрос и известный диапазон ответа. При другом семействе или неподдерживаемом запросе действие пропускается. Защищённый CABCOption в реестре не изменяется.

Первичные описания: [таймер сна](https://learn.microsoft.com/en-us/windows-hardware/customize/power-settings/sleep-settings-sleep-idle-timeout), [таймер экрана](https://learn.microsoft.com/en-us/windows-hardware/customize/power-settings/display-settings-display-idle-timeout), [запись политики питания](https://learn.microsoft.com/en-us/windows/win32/api/powersetting/nf-powersetting-powerwriteacvalueindex), [датчик присутствия](https://learn.microsoft.com/en-us/uwp/api/windows.devices.sensors.humanpresencesettings), [экономия USB](https://learn.microsoft.com/en-us/microsoftteams/devices/pmpsignal-usb-peripherial-power-drain), [системные параметры](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-systemparametersinfow).

## Дизайн

После экспорта «Сохранить» блокируется до изменения действий или иконки. Кнопка оформлена как нейтральные кнопки пресетов. Сообщения об успешном сохранении нет; ошибки по-прежнему объясняются в окне. Отпечаток сохранённого состояния существует только в памяти до закрытия приложения.

Новая реализация следует тёмным Параметрам Windows 11 и Fluent: системный Segoe UI Variable Text, Segoe Fluent Icons, системная акцентная палитра и сине-серый градиент поверх Mica или тёмной основы. Категории подсвечиваются при наведении и затемняются при нажатии, без обводки выбора; плавно раскрывают содержимое. Полоса прокрутки находится сбоку от карточек, движение плавное с пружинным отскоком на границах. Старые шрифты не встраиваются. Концептуальная структура, размеры и цветовые ресурсы описаны в DESIGN.md. Окно остаётся тёмным независимо от системной темы.

## Файлы и сборка

Приложение не сохраняет собственные настройки в файлы или реестр. При экспорте рядом с выбранной целью создаётся временный .ap-*.tmp, который переименовывается или удаляется при завершении; аварийное завершение может оставить такой файл. Windows самостоятельно обслуживает историю системных диалогов и кэши. Исполнители изменяют только выбранные системные параметры; Windows/ASUS могут сохранять эти изменения штатным способом.

Конструктор встраивает готовый исполнитель и собирает PE-ресурсы конфигурации и иконки в памяти. Windows UpdateResource не вызывается; дополнительные RCX-файлы не требуются. Ресурсы версии удаляются: у созданного EXE отсутствуют FileVersion и ProductVersion, поэтому Проводник не показывает строку версии в подсказке. На компьютере пользователя компилятор, PowerShell и VBScript не запускаются, собственный runtime не распаковывается. Обычные исполнители не показывают окон, не создают отчётов, служб, задач и ассоциаций.

Нативные диалоги сохраняют обычное оформление Проводника. Флаги FOS_DONTADDTORECENT и FOS_NOCHANGEDIR ограничивают историю недавних документов и изменение рабочей папки; FOS_NOTESTFILECREATE отключает предварительное создание целевого файла. Эти флаги не отключают все системные записи оболочки Windows и не очищают существующую историю пользователя.

Для разработки выполнить Source\Build.ps1 -SkipPresets в Windows PowerShell 5.1. Используется штатный csc.exe и системные WPF-сборки. Промежуточные файлы находятся в Source\Build. Ключ -SkipPresets обновляет только конструктор и не восстанавливает удалённые готовые режимы. Без него дополнительно создаются Autonomy.exe и Performance.exe.

Исходники и встроенные ICO находятся в Source. Проверки и их артефакты — Tests; для использования программы они не нужны. VerifyUi.ps1 и VerifyPresets.ps1 выполняются с -STA. VerifyExport.ps1 проверяет PE-конфигурации и иконки без выполнения системных действий. Проверки, которые реально переключают режимы или частоту, сохраняют и восстанавливают исходные настройки; их не следует запускать одновременно с ручной настройкой системы.

## Совместимость

Внутренний WNF-механизм энергосбережения и служебный канал ASUS проверены на установленной системе. Совместимость со всеми будущими версиями Windows и всеми ноутбуками ASUS не гарантируется. Нет ScreenXpert/поддержки вентиляторов — шаг пропускается. Яркость меняется только у активных дисплеев с WMI-поддержкой. Пользовательский режим питания задаётся отдельно от энергосбережения, а эффективный режим определяется Windows.

Диагностика исполнителей доступна только по явным аргументам --status --report <файл>, --restore <снимок> --report <файл> и --skip-fan. При обычном запуске файлы диагностики не создаются. Проверки описаны в Tests\RESULTS.md.

Диагностический снимок WindowsState охватывает прежние параметры питания, энергосбережения, яркости и аудио. `--restore` не восстанавливает новые дополнительные функции; для функциональных тестов они снимаются и возвращаются отдельно. Не используйте прежний снимок как универсальную резервную копию всех пунктов «Дополнительно».
