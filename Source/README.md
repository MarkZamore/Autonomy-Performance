# Автономность и производительность

Портативный конструктор для Windows 11 x64 — Autonomy&Performance.exe в корне проекта. Дополнительная установка не требуется: используются включённый в Windows .NET Framework 4.8 и системные API. Программа и создаваемые EXE работают по отдельности.

## Использование

Слева раскройте нужные категории и выберите действия. Справа находится нумерованный предпросмотр, который можно выделить и скопировать. Внизу слева — пресеты «Производительность» и «Автономность»: они заменяют действия целиком, отключают изменение частоты дисплея и сохраняют выбранную иконку. После выбора пресета настройки можно изменить вручную. Нажатие пресета не применяет настройки к компьютеру и не создаёт файл.

«Автономность»: включить энергосбережение и тихий режим вентиляторов. «Производительность»: выключить энергосбережение, выбрать производительный режим вентиляторов и оптимальную производительность Windows, установить яркость и громкость 100%. Состояние отключения звука сохраняется.

Кнопка иконки открывает пять встроенных вариантов и выбор пользовательского ICO. Выбор встроенной иконки действует до закрытия программы. Пользовательская ICO сбрасывается после успешного сохранения; если файл удалён, используется иконка программы. При каждом сохранении открывается выбор места и имени, первоначально на рабочем столе, с именем Режим.exe.

В разделе дисплея можно изменить частоту одного экрана. Список зависит от текущего разрешения и возможностей драйвера. EXE запоминает идентификатор монитора и при запуске заново проверяет доступность режима. Отключённый монитор или недоступная частота молча пропускаются. Разрешение и частота другого экрана не меняются. Клонированные источники с несколькими мониторами не предлагаются.

## Дизайн

Новая реализация следует тёмным Параметрам Windows 11 и Fluent: системный Segoe UI Variable Text, Segoe Fluent Icons, системная акцентная палитра и Mica с однотонным резервом. Старые шрифты не встраиваются. Концептуальная структура, размеры и цветовые ресурсы описаны в DESIGN.md. Окно остаётся тёмным независимо от системной темы.

## Файлы и сборка

Приложение не сохраняет собственные настройки в файлы или реестр. При экспорте рядом с выбранной целью создаётся временный .ap-*.tmp, который переименовывается или удаляется при завершении; аварийное завершение может оставить такой файл. Windows самостоятельно обслуживает историю системных диалогов и кэши. Исполнители изменяют только выбранные системные параметры; Windows/ASUS могут сохранять эти изменения штатным способом.

Конструктор встраивает готовый исполнитель и собирает PE-ресурсы конфигурации и иконки в памяти. Windows UpdateResource не вызывается; дополнительные RCX-файлы не требуются. Ресурсы версии удаляются: у созданного EXE отсутствуют FileVersion и ProductVersion, поэтому Проводник не показывает строку версии в подсказке. На компьютере пользователя компилятор, PowerShell и VBScript не запускаются, собственный runtime не распаковывается. Обычные исполнители не показывают окон, не создают отчётов, служб, задач и ассоциаций.

Нативные диалоги сохраняют обычное оформление Проводника. Флаги FOS_DONTADDTORECENT и FOS_NOCHANGEDIR ограничивают историю недавних документов и изменение рабочей папки; FOS_NOTESTFILECREATE отключает предварительное создание целевого файла. Эти флаги не отключают все системные записи оболочки Windows и не очищают существующую историю пользователя.

Для разработки выполнить Source\Build.ps1 -SkipPresets в Windows PowerShell 5.1. Используется штатный csc.exe и системные WPF-сборки. Промежуточные файлы находятся в Source\Build. Ключ -SkipPresets обновляет только конструктор и не восстанавливает удалённые готовые режимы. Без него дополнительно создаются Autonomy.exe и Performance.exe.

Исходники и встроенные ICO находятся в Source. Проверки и их артефакты — Tests; для использования программы они не нужны. VerifyUi.ps1 и VerifyPresets.ps1 выполняются с -STA. VerifyExport.ps1 проверяет PE-конфигурации и иконки без выполнения системных действий. Проверки, которые реально переключают режимы или частоту, сохраняют и восстанавливают исходные настройки; их не следует запускать одновременно с ручной настройкой системы.

## Совместимость

Внутренний WNF-механизм энергосбережения и служебный канал ASUS проверены на установленной системе. Совместимость со всеми будущими версиями Windows и всеми ноутбуками ASUS не гарантируется. Нет ScreenXpert/поддержки вентиляторов — шаг пропускается. Яркость меняется только у активных дисплеев с WMI-поддержкой. Пользовательский режим питания задаётся отдельно от энергосбережения, а эффективный режим определяется Windows.

Диагностика исполнителей доступна только по явным аргументам --status --report <файл>, --restore <снимок> --report <файл> и --skip-fan. При обычном запуске файлы диагностики не создаются. Проверки описаны в Tests\RESULTS.md.
